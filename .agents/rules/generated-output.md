# Generated output

Prefix: GEN. The file the tool writes is its public contract. Projects commit it and diff it, so changes to its shape reach every user on their next `go generate`.

- **GEN1:** The first line stays `// Code generated by oapixconstgen. DO NOT EDIT.` followed by a blank line. Go tooling and linters recognize generated files by that exact form, and the `TestRun` cases assert it.
- **GEN2:** Output is deterministic for a given spec. `collectConstants` sorts by the spec name because `spec.XConstants` is a map with random iteration order. Do not drop the sort or emit anything that varies between runs (timestamps, versions, paths), because downstream codegen-drift checks compare the committed file with a fresh run.
- **GEN3:** The output goes through `go/format.Source` before it is written, and a format error fails the run with exit code 1 and no file. Keep the write after the format step so a broken spec never replaces a good file.
- **GEN4:** A spec with no usable constants exits 0 without writing or deleting anything. Keep that, since `go generate` runs over packages whose spec may have no `x-constants` yet.
- **GEN5:** Adding a type key means a new `openAPIType*` constant and a `typeFormats` entry in `main.go`, a case in `TestCollectConstants`, an entry in `.fixtures/api.yml` with a `TestRun` assertion, and a row in the type table of `docs/x-constants.md`. The verb must print a Go literal of that type for every value YAML can decode for it.
- **GEN6:** A change to naming (`toExportedName`), ordering, value formatting, file mode or the defaults of `-out`, `-file` and `-pkg` changes every user's generated file. It needs a CHANGELOG entry that says so, and `docs/x-constants.md` or `docs/command-line.md` updated in the same change.
