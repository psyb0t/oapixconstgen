# oapixconstgen

Instructions for coding agents (Codex, Claude Code and others) and for people changing this repository. Users of the tool want the documentation site, https://psyb0t.github.io/oapixconstgen/, not this file.

## Agent setup

`CLAUDE.md` is a committed symlink to `AGENTS.md`, and `.claude` is a committed symlink to `.agents`, so Claude Code reads the same instructions, rules and skills as Codex. Claude's Edit and Write tools refuse to write through a symlink, so edit `AGENTS.md` and `.agents/rules/*.md` directly.

## What it is

A Go command-line tool, installed with `go install github.com/psyb0t/oapixconstgen@latest` or as a `go get -tool` dependency. It reads the top-level `x-constants` map of an OpenAPI spec (`type key -> name -> value`) and writes one Go file with a `const` block of typed constants, so a service's Go code uses the values its spec declares. Other projects run it from `go generate`; psyb0t/docker-monero, for example, generates its API limits with it.

## Architecture

Everything is in `main.go`, `package main`:

- `main` calls `run(os.Args[1:], os.Stderr)` and exits with its return value. `run` returns 0 or 1 and never calls `os.Exit` itself, so tests drive it directly.
- `run` parses the four flags (`-spec`, `-out`, `-file`, `-pkg`) on its own `flag.FlagSet` with `ContinueOnError`, reads the spec, unmarshals it with `gopkg.in/yaml.v3` into `openAPISpec` (only `x-constants` is mapped), then calls the two helpers and writes the file with `filePerms` (`0o600`).
- `collectConstants` keeps the type keys found in its `typeFormats` map (the 14 `openAPIType*` constants, each with its `fmt` verb), skips unknown ones silently, and sorts the result by the spec name.
- `generateCode` prints each constant with `fmt` into a buffer and runs `go/format.Source` over it. A value or name that does not make valid Go syntax fails here, wrapped with `ctxerrors.Wrap`. It does not type-check, so a duplicate name or an out-of-range value is written and left for the Go compiler.
- `toExportedName` splits on `_` and upper-cases the first byte of each part.

Data flow: flags -> `os.ReadFile` -> `yaml.Unmarshal` -> `collectConstants` -> `generateCode` -> `os.WriteFile`. Logging is `log/slog` with a text handler on the writer passed to `run` (stderr in production).

## Stack

- Go 1.26 (`go 1.26` in `go.mod`, `go_version: "1.26"` in CI).
- Runtime dependencies: `gopkg.in/yaml.v3` and `github.com/psyb0t/ctxerrors`.
- golangci-lint v2 as a `tool` directive in `go.mod`, configured by `.golangci.yml`. All modules are vendored in `vendor/` and committed.
- CI: `.github/workflows/pipeline.yml` calling `go-workflow.yml`, `wait-for-default-branch.yml`, `release-workflow.yml` and `create-badges.yml` from psyb0t/reusable-github-workflows.
- Docs: Jekyll with the just-the-docs theme, built by GitHub Pages from `docs/` on `main`.

## Commands

Go 1.26 and Make for the code, Docker for the docs site.

```bash
make help             # every target
make dep              # go mod tidy and go mod vendor
make lint             # go fix -diff, then golangci-lint
make lint-fix         # go fix and golangci-lint --fix
make test             # go test -race ./...
make test-coverage    # tests with coverage, fails below 90%, writes coverage-percent.txt
make docs             # build the documentation site into .testing/docs-site
```

CI runs `make lint` and `make test-coverage`. If the environment sets `GOFLAGS=-mod=readonly`, run `make lint` with `GOFLAGS=` so `go fix -diff` uses `vendor/` and prints nothing.
